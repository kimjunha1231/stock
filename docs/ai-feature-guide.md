# AI 기능·수요예측 개발 길라잡이

작성 기준: 2026-07-31  
적용 범위: 현대웰니스·현대리바트·현대그린푸드

이 문서는 AI 기능을 개발할 때 “어떤 자료를 모으고, 어떤 계산을 먼저 하고, 화면에 무엇을 보여줄지”를 한 단계씩 설명하는 기준 문서입니다. 세 계열사의 데이터는 하나의 공통 모델로 관리하지만, 상품 특성에 따라 입력값·가중치·차단 조건은 다르게 적용합니다.

## 1. AI 기능의 전체 흐름

```text
검색·SNS·판매 신호 수집
  → 트렌드 급증·급락 판정
  → 기본수요 + 트렌드·시즌·가격 효과로 수요예측
  → 위험점수와 하드 차단 확인
  → 할인·채널·번들 전략 후보 계산
  → 기준선 대비 증분이익 비교
  → AI가 근거를 쉬운 말로 설명
  → 계열사 담당자 승인
  → 실제 결과를 회수해 오차 검증
```

AI는 입고·가격·재고를 직접 변경하지 않습니다. 숫자는 결정론적 수식 엔진이 계산하고, LLM은 계산 결과를 요약하고 확인할 질문을 작성합니다.

## 2. 기능별 입력·계산·결과

| 기능 | 필요한 자료 | 계산/판정 | 화면에 보여줄 결과 |
| --- | --- | --- | --- |
| 트렌드 신호 | 검색량, SNS 언급량, 조회수, 판매량, 프로모션 노출량 | `TrendScore = 0.35×검색 변화 + 0.25×SNS 변화 + 0.30×판매 변화 + 0.10×조회 변화` | 급증·급락 방향, 변화율, 출처, 수집 시각 |
| 트렌드 반영 수요예측 | 판매이력, 품절일, 가격, 할인, 시즌, 요일, TrendScore | `예상수요 = 기본수요 × (1+트렌드효과) × 시즌효과 × 가격효과 × 채널효과` | 예상 일일 판매량, 예측 구간, 소진예상일, 신뢰 상태 |
| 위험재고 탐지 | 현재고, 예상수요, 보관일, 소비기한, 보관·폐기·배송 비용 | `RiskScore = 100 × Σ(신호 중요도 × 상품별 위험 정도)` | 0~100 점수, 정상·주의·위험, 판단 이유 |
| 전략 후보 생성 | 예측수요, 허용 할인·기간·수량·채널, 정책 프로필 | 하드 차단 → 수요 → 손익 → 기준선 비교 → 목표별 정렬 | 최대 3개 전략과 예상 결과 |
| 시뮬레이션 | 수량, 할인율, 기간, 쿠폰·포인트, 배송·프로모션 비용 | `증분이익 = 전략 결과 - 기준선 결과` | 판매량·매출·마진·소진기간·잔여재고 |
| 설명 생성 | 계산 결과, 사용 데이터 기간, 정책·모델 버전 | LLM은 숫자를 변경하지 않고 요약·질문만 생성 | 추천 이유, 주의사항, 다음 확인 항목 |

## 3. 계열사별로 추가할 자료

### 현대웰니스

- 상품·SKU: 성분, 기능, 대상, 로트, 소비기한, 보관조건, 표시·주의사항
- 비용: 배송·포장·수수료, 쿠폰 부담, 반품 검수, 회수·폐기
- 차단: 소비기한·보관조건·표시·리콜·판매 권한이 확인되지 않으면 추천하지 않음
- 트렌드 활용: 검색량과 SNS가 상승해도 건강 관련 표현은 승인된 상품 속성만 사용

### 현대리바트

- 상품·SKU: 모델, 옵션, 크기·중량, 창고 위치, 납기, 설치 필요 여부, 배송 권역
- 비용: 보관 공간, 배송·설치, 파손·재배송·회수·AS
- 차단: 배송·설치 가능량, 주문제작 상태, 반품·AS 조건이 확인되지 않으면 추천하지 않음
- 트렌드 활용: 검색·조회가 늘어도 설치 슬롯과 창고 공간이 부족하면 입고 확대를 보류

### 현대그린푸드

- 상품·SKU: 로트, 소비기한, 온도등급, 보관조건, 원산지·이력추적, 검사상태, 배송창
- 비용: 피킹·포장, 냉장·냉동 배송, 보냉재·에너지, 회수·폐기, 반품
- 차단: 소비기한·보관조건·검사·콜드체인 가능량이 확인되지 않으면 추천하지 않음
- 트렌드 활용: 수요 급증 시 예상 판매량과 냉장·냉동 처리 가능량을 함께 확인해 추가 입고를 검토

## 4. “두바이쫀득쿠키” 같은 트렌드 사례 처리 순서

1. 검색·SNS·조회수·판매량을 일자별로 모읍니다.
2. 전주 대비 변화율과 7일 이동평균을 계산합니다.
3. 한 채널만 급증한 것인지, 여러 신호가 함께 움직이는지 확인합니다.
4. 품절 때문에 판매량이 낮아진 날은 수요 하락으로 학습하지 않습니다.
5. 상승 신호가 지속되면 기본 수요에 트렌드 효과를 더해 입고·프로모션 후보를 계산합니다.
6. 상승이 꺾이면 기존 입고를 유지할 때 남을 재고와 악성재고 전환 가능성을 계산합니다.
7. 담당자에게 “추천”과 함께 근거 기간, 불확실성, 보류 조건을 보여주고 승인받습니다.

## 5. 수요예측 모델 학습 순서

1. 상품·SKU별 일자 판매량, 품절 여부, 가격·할인, 프로모션, 반품·취소, 재고·입고 이력을 최소 28일 이상 적재합니다.
2. 검색·SNS 데이터는 출처·수집시각·키워드·집계 단위를 함께 저장하고 변화율·이동평균을 만듭니다.
3. 예측 기준일 다음 7일·14일 실제 판매량을 학습 정답(label)으로 연결합니다.
4. 이동평균·카테고리 평균을 기준모델로 두고, 트렌드 변수를 추가한 모델과 오차를 비교합니다.
5. 과거로 학습하고 이후 기간으로 검증하는 시간 순서 검증을 사용합니다. 계열사·카테고리별 오차도 별도로 확인합니다.
6. 예측값, 예측 구간, 사용 기간, 모델 버전을 저장합니다. 자료가 적으면 카테고리 평균 또는 “예측 부족”으로 대체합니다.
7. 전략 실행 뒤 실제 판매·매출·잔여재고와 비교해 오차 원인을 기록합니다. 충분히 검증되기 전에는 자동 재학습·자동 입고를 하지 않습니다.

## 6. 개발 시 지켜야 할 경계

- 법규·소유권·소비기한·배송·설치·콜드체인·데이터 품질은 손익 계산보다 먼저 확인합니다.
- 원가는 일반 화면에 노출하지 않고 서버에서만 계산합니다.
- 같은 입력과 같은 `snapshot_id · policy_version · formula_version · model_version`이면 같은 결과가 나와야 합니다.
- LLM 장애 시에도 수식 계산 결과와 장애 사유를 보여주는 대체 경로를 둡니다.
- 실제 판매 결과가 없는 경우 임의의 성과 숫자를 만들지 않고 “미수집”으로 표시합니다.

## 7. 전략 목표 선택

| 목표 | 쉬운 뜻 | 우선 계산값 |
| --- | --- | --- |
| 최대 마진 | 팔고 나서 가장 많이 남는 안 | 증분 기여현금이익·마진율 |
| 빠른 소진 | 정한 기간 안에 재고를 가장 빨리 줄이는 안 | 예상 판매량·소진기간 |
| 최대 매출 | 전체 판매 금액이 가장 커지는 안 | 예상 판매수량 × 판매가격 |
| 위험 최소화 | 폐기·보관·배송·파손 손실을 가장 많이 줄이는 안 | 회피비용·위험손실 |

최종 순위는 하드 차단을 통과한 후보만 대상으로 하며, 최종 실행은 해당 계열사 담당자가 승인합니다.
