# 현대백화점그룹 3개 계열사 통합 AI 재고 의사결정 서비스 개요

## 프로젝트 정의

현대웰니스, 현대리바트, 현대그린푸드의 상품·재고·판매속도·보관기간·시즌/기한과 외부 트렌드 신호를 하나의 운영 화면에서 통합 관리하고, 계열사별 담당 MD가 위험재고 처리 전략을 비교·승인하도록 돕는 B2B 재고 의사결정 지원 서비스입니다.

현재 대상 계열사는 **현대웰니스, 현대리바트, 현대그린푸드**입니다. 계열사마다 상품 특성·보관 조건·판매 채널·처리기한이 다르므로 공통 데이터 모델과 계열사별 정책을 함께 사용합니다. AI는 검색·SNS·판매 신호를 수요예측에 반영해 후보를 만들 뿐 가격이나 재고를 직접 변경하지 않으며, 최종 전략은 해당 계열사의 권한 있는 담당 MD가 검토하고 승인합니다.

1차 검증은 3개 계열사의 대표 상품군을 공통 흐름으로 연결하고 트렌드 반영 수요예측을 검증하는 데 초점을 둡니다. 계열사 간 재고 이동·공동 프로모션은 데이터와 권한 계약을 확인한 뒤 후순위(P2)로 둡니다.

## 해결하려는 문제

같은 상품도 계열사·판매 채널·점포 위치·고객층·노출·시즌에 따라 판매속도가 다릅니다. 따라서 공통 화면에서 통합 현황을 보되, 위험도와 손익 계산은 계열사별 상품 정책과 운영 조건을 적용해야 합니다.

위험재고가 쌓이면 다음 손실이 발생합니다.

- 보관비와 공간 대체가치 증가
- 시즌 종료·품질 저하에 따른 상품가치 하락
- 큰 폭의 할인으로 인한 정상판매 잠식
- 폐기·회수·반품·재포장 비용 증가
- 담당자의 수작업 비교와 승인 지연

## 프로젝트 목표

- 판매속도가 느려지거나 처리기한이 임박한 상품을 계열사 구분 없이 조기에 발견
- 상품·색상·사이즈 단위 위험 원인을 설명
- 할인·타임세일·채널 전환·기부·회수·폐기 등 처리 대안 비교
- 전략별 예상 판매량·소진기간·잔여재고·증분 기여현금이익 계산
- 할인율·처리수량·기간·쿠폰·포인트·배송비를 바꿔 즉시 시뮬레이션
- 계열사별 담당 MD의 승인 시간을 단축하되 사람의 책임선을 유지
- 실행 후 예상값과 실제 판매·마진·잔여재고를 비교

## 사용자와 책임

### 1차 사용자: 계열사별 점포·부서 책임 MD

- 소속 계열사와 담당 점포의 재고·위험 원인 확인
- 계열사 기준선과 AI 추천 전략 비교
- 할인율·처리수량·기간·채널 조건 조정
- 일반 전략 승인 또는 거절
- 승인된 실행 내용을 계열사 매장·물류·운영 담당자에게 전달
- 예상 결과와 실제 결과의 차이 및 원인 기록

### 예외 검토 사용자: 그룹 및 계열사 재고전략 담당자

일반 전략을 대신 승인하지 않습니다. 대규모 손실, 추가 예산, 브랜드·법규·안전 위험, 계열사 간 조정이 필요한 경우에만 예외를 검토합니다.

## 범위

### P0/P1 — 1차 통합 검증 범위

- 현대웰니스·현대리바트·현대그린푸드 상품 및 재고 통합 조회
- 계열사별 상품·카테고리·브랜드·옵션·SKU 기준정보와 공통 식별자 관리
- 계열사별 대표 상품군을 우선 적용하고 상품 특성에 맞는 필수 속성·처리기한을 검증
- 판매이력·재고변동이력은 전략 효과 검증을 위한 데이터로 적재하며, 별도 수기 관리 화면은 제공하지 않음
- 계열사·점포·채널·상품·옵션 단위 재고 위험 탐지
- 계열사별 할인·타임세일·채널 전환·기부·회수·폐기 전략 비교
- 순마진 방어·빠른 소진·최대 매출 시나리오 비교
- 최대 3개의 세부 전략 후보 제시
- 조건 변경 시 예상 판매량·매출·마진·소진기간·잔여재고 즉시 재계산
- 담당 MD 승인 및 실행 결과 회수

### P2 — 후순위 확장 범위

- 계열사 간 동일·유사 상품 비교 및 재고 이동 추천
- 이동수량·이동비용·수신 점포 용량·이동 후 판매속도 계산
- 추가 판매 채널과 신규 상품군 확장
- 계열사·채널 공동 프로모션 및 그룹 단위 재고 최적화
- 교차 계열사 번들상품 구성·재고 예약·매출 배분
- 고객용 읽기 전용 할인·번들상품 조회 화면
- 예측 결과를 반영한 자동 재학습·모델 배포

P2 기능은 P0/P1의 계열사별 손익·승인·실행 결과와 데이터 품질이 검증된 뒤 추가합니다. 계열사 간 이동을 기본 전략으로 가정하지 않습니다.

## 주요 기능 범위(정리본)

### 1) 사용자·계열사 권한 관리

- 로그인·로그아웃·JWT 인증
- 계열사·점포·채널 범위 기반 조회 권한
- 담당 MD와 예외 검토자의 승인 권한

### 2) 통합 상품·재고 데이터 관리

- 계열사 상품·카테고리·브랜드·옵션·SKU 공통 조회
- 현재 재고·판매이력·재고변동이력 적재 및 일괄 갱신
- 일괄 스케줄링과 계열사·상품·채널·위험도 필터
- 원가는 화면에 노출하지 않고 손익·위험 계산에만 사용

### 3) 통합 재고·위험재고 관제

- 계열사 전체 재고수량·재고금액과 정상/위험 비율
- 계열사·카테고리별 위험재고, 장기재고, 판매 부진 우선순위
- 위험점수·등급·판단 이유·과거 판매 추이
- 정해진 주기의 위험재고 재분석과 상세 진단

### 4) AI 판매전략 추천·시뮬레이션

- 담당자 요청 시 할인·쿠폰·포인트·채널·번들 전략 생성
- 순마진 방어·빠른 소진·최대 매출 목적별 최대 3개 후보
- 수량·할인율·기간·비용 조건 변경 및 예상 판매량·매출·이익·잔여재고 재계산
- 하드 차단 조건·추천 근거·신뢰도·하방 경고 표시

### 5) 전략 검토·승인·실행 이력

- AI 추천안 수정·저장·검토 요청
- 승인·거절·재승인·실행 대기·실행 중·완료·실패 상태 관리
- 최종 승인과 조건 변경은 서비스에서 수행
- Microsoft Teams는 승인 결과와 실행 내용을 전달하는 채널로 사용
- 사용자 작업·승인·변경·전달 이력 저장

### 6) 전략 성과 비교

- 전략별 예상 결과와 실제 판매·매출·마진·잔여재고 비교
- 목표 달성률·예측 오차·실행 원인 기록
- 실제 판매 데이터는 원천 시스템에서 회수하며, 초기에는 자동 재학습을 수행하지 않음

초기 범위에서는 교차 계열사 번들상품, 고객용 판매 카탈로그, 자동 재학습·모델 배포를 구현하지 않습니다. 필요한 데이터와 화면 경계만 후속 확장을 위해 준비합니다.

- 통합 대시보드·통계·재고 검색·필터

교차 계열사 번들, 고객용 읽기 전용 화면, 자동 재학습은 네 담당자의 초기 핵심 범위에서 제외하고 후속 확장으로 둡니다.

## AI와 사람의 역할

AI는 계열사별 정책을 반영한 위험 탐지, 판매량·소진기간 예측, 비용 계산, 전략 후보 생성, 추천 이유 설명을 담당합니다. 가격·할인·재고 변경과 실행 확정은 해당 계열사의 담당 MD가 승인합니다.

최종 목적함수는 다음과 같습니다.

```text
max M_inc(s)
= 추가 매출액 + 피한 폐기·보관비
− 정상판매 잠식손실 − 물류·재포장비
− 브랜드 훼손비용 − 반품·CS 비용 − AI 처리원가
```

수요 예측식 `Q_sale`은 이 최종식에 들어갈 예상 판매수량을 계산하는 보조식입니다.

## 현재 구현 수준과 다음 단계

현재 설명 사이트와 제품 화면은 Mock 재고·규칙 기반 위험점수·수식 시뮬레이션·승인 흐름을 검증하는 프로토타입입니다. 실제 서비스 구축 시 계열사별 ERP/POS/WMS·상품 마스터 데이터 계약, 계열사·점포 권한, 승인 감사로그, Teams 전송 API, 실제 판매·정산 결과 회수를 연결합니다.
