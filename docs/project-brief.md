# 현대백화점 다점포 AI 재고 의사결정 서비스 개요

## 프로젝트 정의

현대백화점 점포의 재고수량·판매속도·보관기간·시즌/기한을 비교해 위험재고를 빠르게 발견하고, 담당 MD가 처리 전략을 비교·승인하도록 돕는 B2B 재고 의사결정 지원 서비스입니다.

현대백화점 외 계열사는 이 프로젝트의 대상에서 제외합니다. AI는 가격이나 재고를 직접 변경하지 않으며, 최종 전략은 권한 있는 현대백화점 담당 MD가 검토하고 승인합니다.

1차 계산·실행 검증 기준은 **더현대 서울 직매입 재고**입니다. 현대백화점 다른 점포와 점포 간 재고 이동은 구조만 준비하고 후순위(P2)로 둡니다.

## 해결하려는 문제

같은 상품도 점포 위치·고객층·노출·시즌에 따라 판매속도가 다릅니다. 그러나 1차 서비스는 한 점포 내부의 상품·수량·판매속도·처리기한을 먼저 정확하게 판단하고, 점포 간 비교는 검증 이후에 확장합니다.

위험재고가 쌓이면 다음 손실이 발생합니다.

- 보관비와 공간 대체가치 증가
- 시즌 종료·품질 저하에 따른 상품가치 하락
- 큰 폭의 할인으로 인한 정상판매 잠식
- 폐기·회수·반품·재포장 비용 증가
- 담당자의 수작업 비교와 승인 지연

## 프로젝트 목표

- 판매속도가 느려진 직매입 상품을 조기에 발견
- 상품·색상·사이즈 단위 위험 원인을 설명
- 할인·타임세일·아울렛·기부·폐기 등 처리 대안 비교
- 전략별 예상 판매량·소진기간·잔여재고·증분 기여현금이익 계산
- 할인율·처리수량·기간·쿠폰·포인트·배송비를 바꿔 즉시 시뮬레이션
- 담당 MD의 승인 시간을 단축하되 사람의 책임선을 유지
- 실행 후 예상값과 실제 판매·마진·잔여재고를 비교

## 사용자와 책임

### 1차 사용자: 현대백화점 점포·부서 책임 MD

- 자기 점포의 재고와 위험 원인 확인
- AI 추천 전략과 기준선 비교
- 할인율·처리수량·기간·채널 조건 조정
- 일반 전략 승인 또는 거절
- 승인된 실행 내용을 매장·물류 담당자에게 전달
- 예상 결과와 실제 결과의 차이 및 원인 기록

### 예외 검토 사용자: 현대백화점 본사 재고전략 담당자

일반 전략을 대신 승인하지 않습니다. 대규모 손실, 추가 예산, 브랜드·법규·안전 위험, 점포 간 조정이 필요한 경우에만 예외를 검토합니다.

## 범위

### P0/P1 — 1차 검증 범위

- 더현대 서울 직매입 재고
- 1개월 실증은 의류·신발 등 1~2개 상품군을 우선 적용
- 상품·색상·사이즈 단위 재고 위험 탐지
- 현재 점포 내 할인·타임세일·아울렛·기부·폐기 전략 비교
- 순마진 방어·빠른 소진·최대 매출 시나리오 비교
- 최대 3개의 세부 전략 후보 제시
- 조건 변경 시 예상 판매량·매출·마진·소진기간·잔여재고 즉시 재계산
- 담당 MD 승인 및 실행 결과 회수

### P2 — 후순위 확장 범위

- 현대백화점 다른 점포와 동일 상품 비교
- 점포 간 재고 이동 추천
- 이동수량·이동비용·수신 점포 용량·이동 후 판매속도 계산
- 식품·가구·가전 등 추가 상품군
- 특약매입·임대매장 등 계약 형태별 확장
- 점포·채널 공동 프로모션

P2 기능은 P0/P1의 단일 점포 손익·승인·실행 결과가 검증된 뒤 추가합니다. 점포 간 이동을 기본 전략으로 가정하지 않습니다.

## 핵심 기능

### 1) 재고 현황 대시보드

전체 재고수량·금액, 정상/위험 비율, 상품군별 위험재고, 장기보관 상품, 우선 처리 상품을 보여줍니다.

### 2) 위험재고 탐지

판매속도·현재고·보관일수·시즌/처리기한·사이즈 분포를 분석하고, 위험점수뿐 아니라 판단 원인을 함께 표시합니다.

### 3) AI 처리 전략 생성

- 순마진 극대화: 할인폭을 줄이고 이익을 보호
- 빠른 소진: 처리기한 안에 재고를 빠르게 줄임
- 최대 매출: 판매수량과 외형 매출을 높임

세 가지는 비교 시나리오이며, 최종 선택은 하드 차단 조건을 통과한 대안 중 증분 기여현금이익이 가장 큰 전략으로 합니다.

### 4) 전략 비교·직접 시뮬레이션

담당자는 할인율, 적용수량, 판매기간, 쿠폰·포인트, 배송비, 포장비, 광고비 등을 조정할 수 있습니다. 점포 간 이동수량과 이동비용은 P2에서 추가합니다.

### 5) 승인·전달

승인 전 조건은 자유롭게 조정할 수 있고, 승인 후 조건을 바꾸면 재승인이 필요합니다. Microsoft Teams는 승인된 실행 내용을 전달하는 알림 채널로 사용하며, 최종 승인과 변경은 본 서비스에서만 수행합니다.

### 6) 예상 결과와 실제 결과 비교

예상 판매량·마진·소진기간·잔여재고와 실제 결과를 비교합니다. 행사 노출 부족, 인기 사이즈 품절, 날씨, 경쟁 행사, 운영 문제 등 원인을 구조화해 기록합니다.

## AI와 사람의 역할

AI는 위험 탐지, 판매량·소진기간 예측, 비용 계산, 전략 후보 생성, 추천 이유 설명을 담당합니다. 가격·할인·재고 변경과 실행 확정은 담당 MD가 승인합니다.

최종 목적함수는 다음과 같습니다.

```text
max M_inc(s)
= 추가 매출액 + 피한 폐기·보관비
− 정상판매 잠식손실 − 물류·재포장비
− 브랜드 훼손비용 − 반품·CS 비용 − AI 처리원가
```

수요 예측식 `Q_sale`은 이 최종식에 들어갈 예상 판매수량을 계산하는 보조식입니다.

## 현재 구현 수준과 다음 단계

현재 설명 사이트와 제품 화면은 Mock 재고·규칙 기반 위험점수·수식 시뮬레이션·승인 흐름을 검증하는 프로토타입입니다. 실제 서비스 구축 시 ERP/POS/WMS 데이터 계약, 점포 권한, 승인 감사로그, Teams 전송 API, 실제 판매·정산 결과 회수를 연결합니다.
